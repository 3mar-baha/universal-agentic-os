# Universal Agentic Engineering OS

*إطار عمل بجودة إنتاجية، متعدد المجالات، للتطوير المستقل وتنسيق وكلاء الذكاء الاصطناعي.*

يحوّل Universal Agentic Engineering OS بيان المهمة الخام إلى نتيجة موثَّقة وجاهزة للإنتاج. يجمع النظام بين نموذج تشغيلي ثلاثي الأدوار — **Leader** و**Guide** و**Implementer** — ودورة حياة من أربع مراحل، وهيكل مشروع قياسي من 16 ملفًا، وست مهارات مضمّنة. وتقيَّد الاستقلالية بآليات سلامة صارمة: قاطع دائرة بثلاث محاولات، وثلاثة حرّاس مستقلين للمراجعة الثانية، وتخطيط يضع المواصفة قبل الكود، وتنفيذ يتّخذ من الاختبارات عقدًا ملزمًا داخل git worktree معزولة، وإصدارات منضبطة تقودها سجلات التغيير (changelog).

## لماذا هذا النظام

- **متعدد المجالات بالتصميم.** نموذج تشغيلي واحد يغطي الأنماط الأربعة جميعها — هندسة البرمجيات، والذكاء الاصطناعي/تعلّم الآلة، وأتمتة الأعمال، والبحث العميق — فيتعلّم فريقك ووكلاؤك تخصصًا واحدًا بدلًا من أربعة.
- **استقلالية محكومة ببوابات السلامة.** يتحرك الوكلاء بسرعة داخل مسارات محددة: لا كود بدون مواصفة معتمدة، ولا دمج بدون اختبارات ناجحة، ولا إصدار بدون الحرّاس، ولا محاولة إصلاح رابعة عمياء أبدًا.
- **اقتصاد أدوات مركزي.** تُثبَّت حزم الأدوات الستة المصدرية مرة واحدة في `CLAUDE_TOOLKIT_DIR`، وتُحقن حسب المرحلة ثم تُقلَّم بعدها، فيواكب الإنفاق على السياق العمل الجاري فعليًا.

## المعمارية

يُعد Orca ADE (ORchestrated Cooperative Agents) طبقة التشغيل (runtime) لهذا النظام. يتولى تهيئة الجلسة، والحقن الديناميكي للأدوات والمهارات وقلّمها في كل مرحلة من مراحل دورة الحياة، وإدارة مجمّع git worktree الذي تستخدمه وحدات التنفيذ المتوازية. ويعمل النموذج التشغيلي ثلاثي الأدوار فوق هذه الطبقة:

```
                        +-----------------------+
                        |        LEADER         |
                        | decomposes mission,   |
                        | routes tasks, owns    |
                        | sequencing + outcome  |
                        +-----------+-----------+
                                    |
              tasks + constraints   |    status + results
                +-------------------+-------------------+
                v                                       v
    +-----------------------+               +-----------------------+
    |         GUIDE         |               |     IMPLEMENTERS      |
    | specification         | ------------->| [worktree: feat-a]    |
    | architecture review   |  spec + gates | red -> green ->       |
    | guardrails + gates    | <-------------| refactor cycle        |
    | phase-exit sign-off   |  escalation + | [worktree: bugfix-b]  |
    +-----------------------+  strikes +DIR |                       |
                                            +-----------+-----------+
                                       reviewed merges  |
                                                        v
                                            +-----------------------+
                                            | main: guarded, tagged |
                                            | released via phase 4  |
                                            +-----------------------+
```

يوجّه Leader كل مهمة؛ ويصوغ Guide مواصفتها ويضبط بواباتها؛ وينفّذ المنفّذون (Implementers) دورات red-green-refactor داخل worktree معزولة — بموضوع واحد لكل worktree — ثم يُدمج العمل مجددًا عبر تكاملات مُراجَعة ومعتمَدة.

| الدور | المسؤوليات | صلاحيات القرار | ما ليس من صلاحياته صراحةً |
| --- | --- | --- | --- |
| **Leader** | تفكيك المهمة الكبرى، وتوجيه المهام، وترتيبها، والمساءلة النهائية | ترتيب المهام، وحدود النطاق، والتوجيه، وصلاحية الإيقاف | اعتماد الجودة — فهذا من اختصاص Guide |
| **Guide** | المواصفات، ومراجعة المعمارية، وضوابط الحماية، وبوابات الجودة؛ واعتماد الخروج من كل مرحلة | قبول المواصفة، والموافقة على الخروج من المرحلة، والموافقة على الفرضية المعدَّلة، وتفعيل قاطع الدائرة | إعادة توجيه المهام — فهذا من اختصاص Leader |
| **Implementer** | دورات TDD مصغّرة (red وgreen وrefactor) داخل git worktree معزولة، بموضوع واحد لكل worktree | الأسلوب التقني في حدود المواصفة، وتفصيل الالتزامات (commits)، وهيكل الاختبارات | توسيع النطاق أو إعادة تعريف معايير القبول |

## دورة الحياة من أربع مراحل

| المرحلة | الدور القائد | الأنشطة الرئيسية | معايير الخروج | المهارات الأساسية |
| --- | --- | --- | --- | --- |
| 1. الاكتشاف والإطلاق | Leader | اكتشاف سقراطي، وتحقق إلزامي من مسار النشر، وإنشاء الهيكل القياسي المكوّن من 16 ملفًا | إيداع الهيكل على `main`؛ وتثبيت مسار النشر؛ وتوثيق موجز الاكتشاف في مستندات الرؤية والمعمارية والقرارات | `agentic-project-launcher` و`preflight-system-doctor` و`session-context-primer` |
| 2. التصميم والتوجيه | Guide | المواصفات، والخطة، والحقن الديناميكي لأدوات المرحلة القادمة ومهاراتها | مواصفة معتمدة؛ وقائمة أعمال مرتبة حسب الأولوية؛ وحقن مجموعة السياق الصحيحة للمرحلة | `claude-stage-orchestrator` |
| 3. التنفيذ والتحقق | Implementer | دورات TDD مصغّرة (red وgreen وrefactor) في worktree معزولة متوازية | نجاح حزمة الاختبارات كاملة؛ ودمج المواضيع عبر تكاملات مُراجَعة؛ ومُدخل في changelog لكل موضوع مدمج | `circuit-breaker-guard` |
| 4. التقوية والإصدار | Guide | بوابات الجودة، وحرّاس المراجعة الثانية، والتغليف، والإصدار | اجتياز Clean Code Guard وTest Guard وDocs Guard؛ ونجاح CI؛ ونشر إصدار مُوسَم | `circuit-breaker-guard` و`github-release-packager` |

## البدء السريع

```sh
# 1. Clone this repository
git clone https://github.com/madaar-team/universal-agentic-os.git
cd universal-agentic-os

# 2. تهيئة بأمر واحد: حزم الأدوات + خطّافات git + CLI على PATH + تقرير doctor
bash scripts/uos.sh init

# 3أ. ابدأ مشروعًا جديدًا محكومًا (الهيكل القياسي + بيئة التشغيل كاملة)
uos new my-project ~/Projects

# 3ب. ...أو اعمل داخل مستودع قائم: افتح وكيلك هناك والصق docs/05-INITIAL-PROMPT.md —
#     والوكلاء غير Claude Code ينطلقون من AGENTS.md تلقائيًا.
```

حافظ على تحديث حزمة الأدوات بالأمر `bash scripts/sync-toolkit.sh`.

### مشغّل Vantrilex (ويندوز)

[`vantrilex.ps1`](vantrilex.ps1) هو منسّق وكلاء البرمجة التفاعلي — مشغّل واحد لـ **Claude Code وOpenCode وCodex**، وتهيئة جلسة كاملة لا مجرد ضبط بيئة:

1. **نوع البروموت أولًا**: بدون بروموت؛ **مشروع جديد بتوثيق كامل** (يحقن الموجّه الافتتاحي الشامل مستخرجًا مباشرة من `docs/05-INITIAL-PROMPT.md` — يبتلع توثيقك قراءةً فقط ويبدأ المرحلة 2 عبر TDD)؛ **مشروع جديد من فكرة** (مقابلة grill-me سقراطية ← ثم تأليف جناح التوثيق القياسي كاملًا ← ثم العمل وفق سير العمل المحكوم)؛ أو **متابعة مشروع قائم** (تهيئة السياق من الـcheckpoint، واحترام مسار BLOCKED لقاطع الدائرة، واستئناف أول معلمة مفتوحة بـ TDD صارم).
2. **المزوّد**: DeepSeek مباشر، بوابة OrcaRouter المجانية، Ox Alpha عبر OpenRouter (سياق مليون)، أو أي endpoint مخصص.
3. **الأداة**: Claude Code (ربط متغيرات Anthropic)، OpenCode (مفاتيح المزوّدين القياسية + `-m provider/model`)، أو Codex (`-c model_provider` فوق endpoint متوافق مع OpenAI). الترجمة بين المزوّد والأداة تلقائية؛ والتركيبات غير المدعومة تُنبَّه بدل أن تفشل بصمت.
4. **مستوى الجهد** حتى Ultracode (يُطبَّق حيث تدعمه الأداة)، ثم مسار المشروع.
5. **تهيئة الجلسة**: يوفّر حزم الأدوات الست إن غابت، ويثبّت بيئة تشغيل النظام في المشروع إن لم تكن موجودة (خطّافات + settings، سكربتات دورة الحياة، الميتا-سكيل، `.mcp.json` مثبّت، إعدادات lint) — فيتحمل MCP والمهارات والخطّافات إلى الجلسة مباشرة.
6. **يطلق الأداة المختارة** والبروموت المختار أول رسالة فيها.

لا مفاتيح مخزنة في السكربت: البيئة ← ملف `.env.vantrilex` المستثنى من git (حفظ اختياري) ← لصق تفاعلي مقنّع لآخر 6 أحرف.

**مُتحقق منه لا مُفترض**: منطق الترجمة بين المزوّد والأداة يعيش في دالة نقية واحدة تمارسها مصفوفة اختبار ذاتي دون اتصال تغطي كل تركيبة (أداة × مزوّد):

```powershell
powershell -ExecutionPolicy Bypass -File vantrilex.ps1 -SelfTest
```

ويشغّل CI تلك المصفوفة عند كل دفع، إضافةً إلى اختبار إطلاق حقيقي ينفّذ `--version` لكل أداة فعليًا (`@anthropic-ai/claude-code` و`opencode-ai` و`@openai/codex`).

```powershell
powershell -ExecutionPolicy Bypass -File vantrilex.ps1
```

### الأمان وتدوير المفاتيح

- هذا المستودع يشحن **صفر أسرار** — الفحص قبل الالتزام يرفض صيغ مفاتيح API المعرومة ورؤوس Bearer والإسنادات الشبيهة بالاعتمادات في كل كوميت.
- مفاتيح المشغّل تُحل من بيئتك أو `.env.vantrilex` المستثنى؛ لا تلتقط ذلك الملف أبدًا ولا تلصق مفاتيح في issues أو محادثات.
- **دوّر فورًا** أي مفتاح ظهر نصًا صريحًا في أي مكان (محادثة، لقطة شاشة، تاريخ مستودع): DeepSeek ← لوحة المنصة ← API keys ← حذف وإنشاء؛ OpenRouter ← Settings ← Keys ← أنشئ جديدًا وأبطل القديم؛ Orca ← لوحة المزوّد. حدّث القيمة في بيئتك أو `.env.vantrilex` بعدها — لا شيء آخر يشير إليها.
- إذا وصل سرٌّ إلى تاريخ git فالحل هو التدوير؛ إعادة كتابة التاريخ لا تسحب ما تسرب.

تُشغَّل الجلسات على أساس بروتوكول MCP مثبّت — يفرض ملف [`.mcp.json`](.mcp.json) خمسة خوادم أساسية (`fetch` و`brave-search` و`sequential-thinking` و`filesystem` و`git`؛ والاعتمادات بأسماء متغيرات البيئة فقط) — ويمنح [.devcontainer/](.devcontainer/) تكافؤ بيئة بأمر واحد للصناديق المحلية والسحابية، محمّلًا سلفًا بحزم الأدوات الستّ عبر `postCreateCommand`.

تبدأ من مستودع مهيّأ سلفًا بهيكل النظام؟ ملف [docs/05-INITIAL-PROMPT.md](docs/05-INITIAL-PROMPT.md) هو الموجّه الافتتاحي الشامل للمشاريع — الصقه في أي جلسة وكيل جديدة للتحقق من حزمة الأدوات المركزية ذات الحزم الستّ، وابتلاع المواصفات الموجودة والتحقق منها، وتوصيل الخطّافات وواجهة `uos`، وتوليد `CLAUDE.md` مفصّل على المشروع، وتثبيت الـ checkpoint، ثم البدء فورًا ببناء المرحلة 2 عبر TDD.

## واجهة `uos` السطرية

نقطة دخول واحدة لكل ما سبق. ثبّتها بالأمر `bash scripts/uos.sh install` (تربطها بمسار `~/.local/bin`)، أو استدعها مباشرة:

| الأمر | ما يفعله |
| --- | --- |
| `uos init` | تهيئة الجهاز بأمر واحد: يوفّر حزم الأدوات الست ويتحقق منها، ويفعّل خطّافات git، ويثبّت CLI على PATH، ويختم بتقرير `doctor` |
| `uos new <NAME> [DIR]` | ينشئ مشروعًا جديدًا محكومًا: الهيكل القياسي ذو الـ16 ملفًا بمحتوى بذري حقيقي، checkpoint حي، بيئة تشغيل النظام مدمجة (خطّافات، سكربتات، الميتا-سكيل، أساس MCP)، وكوميت أول |
| `uos ingest` | يقرأ كل المواصفات في `docs/` ويطابق مراجعها المتقاطعة — قراءةً فقط؛ يكتب `.claude/spec-index.md` لتهيئة سياق الوكلاء ويفشل عند أي مرجع مكسور |
| `uos plan` | يعرض مخطط معالم الـ checkpoint على شكل مسارات عمل قابلة للتوزيع |
| `uos dispatch <stream> [phase]` | يؤمّن شجرة عمل git معزولة في `.worktrees/<stream>` على الفرع `feature/<stream>`، محمّلة سلفًا بحزمة سياق المرحلة |
| `uos merge <stream> [--keep]` | يفحص فروقات المسار (`bash -n` وshellcheck وmarkdownlint)، يدمج بـ `--no-ff`، ينظّف الشجرة، ويختم الـ checkpoint |
| `uos graph [--check]` | يزامن شجرة المستودع داخل مخطط Mermaid محدود بمؤشرات في مستند المعمارية؛ ويفشل `--check` عند تقادم المخطط |
| `uos decide <TITLE>` | يُلحق سجل قرار معماري (ADR) قابلًا للتدقيق بسجل القرارات (`docs/09-DECISIONS.md` أو `docs/03-DECISIONS.md`) |
| `uos doctor` | تشخيصات بيئة خلال أجزاء من الثانية: بيئات التشغيل، ربط الخطّافات، وجود مفاتيح API، سلامة حزمة الأدوات |
| `uos ship [--release]` | يشغّل كل بوابات الجودة المحلية (وتشمل الآن اتساق الإصدار بين سجل التغيير والشارات وواجهة CLI، وتحديث مخطط المعمارية) ويطبع قائمة الإصدار؛ وخيار `--release` يفتح مسودة إصدار GitHub عبر `gh` لتنشرها أنت |
| `uos release <X.Y.Z>` | نشر بأمر واحد: يستخرج قسم الإصدار من سجل التغيير كملاحظات، ثم يوسم ويدفع وينشئ إصدار GitHub (وخيار `--draft` للمراجعة أولًا)؛ ويرفع workflow دفع التاغ الأرشيف المصدرّي إلى صفحة الإصدار تلقائيًا |
| `uos status` | بطاقة ASCII مكوّنة من ثلاثة أسطر: المرحلة النشطة، المعلَمة النشطة، حالة الاختبارات |

## المهارات المضمّنة

| المهارة | ما تفعله | مرحلة دورة الحياة |
| --- | --- | --- |
| [`universal-agentic-workflow`](skills/universal-agentic-workflow.md) | المهارة الفوقية الشاملة: دليل التشغيل الكامل للنظام — النموذج الثلاثي، دورة الحياة رباعية المراحل، تدوير حزم الأدوات الستّ، أشجار العمل المتوازية، وكل الثوابت وبوابات السلامة | تُحمَّل مرة واحدة عند بدء الجلسة، في كل المراحل |
| [`agentic-project-launcher`](skills/agentic-project-launcher.md) | تُشغّل الاكتشاف السقراطي، وتُكمل التحقق من مسار النشر، وتُنشئ الهيكل القياسي المكوّن من 16 ملفًا | 1. الاكتشاف والإطلاق |
| [`claude-stage-orchestrator`](skills/claude-stage-orchestrator.md) | تُحقن عبر Orca ADE المهارات وأصول حزمة الأدوات والمستندات التي تحتاجها المرحلة تحديدًا — وتُقلّم الباقي | الانتقال بين المراحل في المراحل الأربع جميعها |
| [`session-context-primer`](skills/session-context-primer.md) | تُعيد بناء سياق العمل الأساسي في نحو عشر ثوانٍ عند بداية الجلسة، وتُصدر كتلة CONTEXT ANCHOR | تهيئة الجلسة، في كل مرحلة |
| [`circuit-breaker-guard`](skills/circuit-breaker-guard.md) | تتتبع محاولات الإصلاح الفاشلة لكل عيب، وتفرض توقفًا كاملًا مع تقرير حادثة تشخيصي عند المحاولة الثالثة | 3. التنفيذ والتحقق، وتبقى مفعّلة طوال المرحلة 4 |
| [`preflight-system-doctor`](skills/preflight-system-doctor.md) | تتحقق من سلامة البيئة وبيئات التشغيل والإعدادات ومساحة العمل؛ وتحجب التنفيذ عند الإخفاقات الحرجة | فحص تمهيدي قبل أي مرحلة، بدءًا من المرحلة 1 |
| [`github-release-packager`](skills/github-release-packager.md) | تُنشئ ملفات README ثنائية اللغة متدرجة المستويات، وتدير الإصدارات من ملاحظات مشتقة من سجل التغيير وصولًا إلى التحقق بعد الإصدار | 4. التقوية والإصدار |

## تعدد المجالات

تتقاسم أربعة أنماط نموذجًا تشغيليًا واحدًا — راجع [docs/01-MULTI-DOMAIN-ARCHETYPES.md](docs/01-MULTI-DOMAIN-ARCHETYPES.md):

- **هندسة البرمجيات** — تسليم تطبيقات وخدمات إنتاجية بالمواصفة أولًا، مع دورات TDD مصغّرة موزعة على worktree متعددة.
- **الذكاء الاصطناعي/تعلّم الآلة** — خطوط بيانات وأدوات تدريب وتقييم وميزات مدعومة بالنماذج، تخضع للبوابات نفسها التي يخضع لها أي كود آخر.
- **أتمتة الأعمال** — تدفقات عمليات وتكاملات تُسلَّم بوصفها تغييرات موثَّقة وقابلة للاختبار والتدقيق.
- **البحث العميق** — تحقيق منظم مدعوم بسجلات أدلة وأساليب قابلة لإعادة الإنتاج وتوثيق يُسلَّم كمخرج نهائي.

## السلامة

الاستقلالية بلا مكابح عبءٌ لا ميزة. يأتي هذا النظام بثلاثة من هذه المكابح كمعدات قياسية:

- **قاطع الدائرة بثلاث محاولات.** إذا صمد العيب نفسه أمام 3 محاولات إصلاح فاشلة متتالية، يتوقف التنفيذ كله فورًا — لا محاولة إصلاح رابعة عمياء أبدًا — ويُصدر تقرير حادثة تشخيصي يتضمن: العَرَض، وسجل الفرضيات مع دليل عن كل محاولة، والأسباب الجذرية مرتبة حسب الاحتمال، وإجراءات فك التعطل الموصى بها. ولا تُصفَّر المحاولات إلا حين يعتمد Guide فرضية معدَّلة.
- **ثلاثة حرّاس للمراجعة الثانية.** يخضع كل تغيير لمراجعة مستقلة بعد التنفيذ في المرحلة 4: Clean Code Guard وTest Guard وDocs Guard. وثقة المؤلف ليست الفحص الأخير أبدًا.
- **نطاق تأثير محدود.** تتحقق مهارة preflight-system-doctor من سلامة الجهاز قبل أي تشغيل، ويبقى العمل المتوازي معزولًا بموضوع واحد لكل worktree، وتعيش الأسرار في `.env` وحده — ويُشار إليها بالاسم، لا بالقيمة أبدًا.

## شكر وتقدير

يقوم هذا الإطار على ست حزم أدوات مصدرية، تُثبَّت مرة واحدة في `CLAUDE_TOOLKIT_DIR` بواسطة `scripts/setup-toolkit.sh` ويُعاد تحديثها بواسطة `scripts/sync-toolkit.sh`:

- [everything-claude-code](https://github.com/worldflowai/everything-claude-code) — إعدادات وأوامر وسير عمل واسعة لـ Claude Code
- [mattpocock-skills](https://github.com/mattpocock/skills) — مهارات موجّهة إلى TypeScript وتجربة المطوّر
- [ponytail](https://github.com/dietrichgebert/ponytail) — بساطة جذرية: أصغر تجريد يفي بالغرض، بلا ميزات تخمينية
- [guard-skills](https://github.com/amElnagdy/guard-skills) — بوابات جودة دفاعية وحرّاس مراجعة
- [cybersecurity-skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills) — مهارات مراجعة أمنية وتقوية
- [agency-agents](https://github.com/msitarzewski/agency-agents) — شخصيات وكلاء متخصصة لسير عمل الوكالات

## خارطة الطريق

- حزم انطلاق لكل مجال تُهيّئ الهيكل المكوّن من 16 ملفًا مسبقًا بأهداف Makefile ومهام CI خاصة بكل نمط.
- كتالوج قابل للتوسيع من حرّاس إضافيين للمراجعة الثانية إلى جانب Clean Code Guard وTest Guard وDocs Guard.
- ملفات تعريف لحزمة الأدوات واعية بالنمط تختار الحزم مسبقًا من حزم الأدوات الستة المصدرية لحظة الحقن.
- نسخ بلغات إضافية إلى جانب النسخة الإنجليزية الأصلية والنسخة العربية الكاملة.
